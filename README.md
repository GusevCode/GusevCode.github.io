# Coca-Cola Expert

Учебная экспертная система выбора колы по предпочтениям пользователя. Дисциплина: «Основы интеллектуальных систем». Автор: Гусев Алексей, группа СГН3-72Б. Требования описаны в [.docs/PASSPORT.md](.docs/PASSPORT.md).

**20 напитков, 12 числовых атрибутов на объект, 27 вопросов и параметров, 85 правил: 77 правил начисления баллов и 8 правил вывода.** Дополнительные факты: наличие сахара, вкус, происхождение бренда, условный уровень кофеина и бренд. Оценки условны: это не измерения состава, актуальные цены или рекомендации по здоровью.

В полной консультации реально задаётся **от 21 до 27 вопросов**: правила вывода пропускают не более шести. Минимум проверяется исчерпывающим перебором **3600 сочетаний** всех вариантов, включая нейтральные, для параметров — источников вывода (`occasion`, `healthGoals`, `favoriteFlavor`, `brandLoyalty`, `timeOfDay`); остальные вопросы получают нейтральный ответ. Например, сочетание `everyday`, `diet`, `herbal`, `familiar`, `evening` пропускает шесть вопросов и оставляет 21. При добровольном досрочном завершении вопросов может быть меньше.

## Запуск локально

В терминале в папке проекта выполните:

```sh
python -m http.server 8000
```

Откройте [http://localhost:8000](http://localhost:8000). Остановка — Ctrl+C. При открытии через `file://` загрузка JSON с помощью `fetch()` блокируется; интерфейс объяснит, как запустить сервер.

Установка пакетов и сборка не нужны. Используются HTML, CSS, нативные модули JavaScript и JSON. Внешних библиотек, шрифтов и CDN нет. Фотографии упаковки и оригинальные иллюстрации хранятся локально; атрибуция приведена ниже. Ответы существуют в памяти вкладки и исчезают после перезагрузки.

## Тестирование

Нужен Node.js 25. Все тесты:

```sh
node --test tests/
```

Также доступна команда `npm test`. Отдельная проверка кодировки:

```sh
node tests/encoding.test.mjs
```

Тесты читают JSON через файловую систему и проверяют требования паспорта, ссылки, покрытие вариантов правилами, прямой вывод до неподвижной точки, циклы, приоритет пользовательских фактов, пропуск вопросов, минимальное число реально заданных вопросов полным перебором, нейтральные ответы, возврат, перезапуск, операции и отрицательные веса, нормализацию, сортировку и объяснения.

Проверка кодировки обходит все файлы `data/`, `js/`, `tests/`, все SVG в `img/`, а также `index.html`, `style.css`, `README.md`: требует корректный UTF-8 без BOM, кириллицу в каждом файле (в SVG — в доступном описании), отсутствие двух вопросительных знаков подряд и символа замены U+FFFD. Отдельные тесты проверяют существование и структуру SVG, самостоятельность иллюстраций, полноту представлений хранилищ, экранирование JSON и точность снимка РБД. Проверяются также все 20 изображений напитков, атрибуция 17 JPEG, три SVG-заглушки, выбор трёх положительных причин и структура живого и итогового рейтингов.

## Использование

- **Консультация**: каждый вопрос сопровождается иллюстрацией; после каждого ответа — топ-5 с баллами, шкалами и стрелками изменения мест. Выведенные факты и пропущенные вопросы показаны отдельно. Нейтральный ответ ничего не добавляет. Ссылки «Открыть РБД» и «Открыть базу вопросов» сразу переводят к нужному подразделу.
- Лидер живого и итогового рейтинга — крупная карточка с фото, брендом, описанием, оценкой и тремя наибольшими положительными вкладами с кодами правил. Остальные места показаны компактными строками с миниатюрами. До ответов видно «Пока все варианты равны». Смена лидера сопровождается коротким появлением; настройка `prefers-reduced-motion` отключает анимацию. Цветные акценты зависят от вкуса, фон и шкалы используют градиенты, иллюстрация вопроса увеличена на компьютере и остаётся компактной на телефоне.
- **Назад** удаляет последний ответ и пересчитывает сеанс из оставшейся цепочки. **Начать заново** очищает ответы и выводы. **Завершить досрочно** показывает итог с возможностью продолжить.
- Итог содержит **все 20 объектов**, баллы, раскрываемое объяснение с вкладами правил и цепочку ответов с миниатюрами и выводами для графа выбора в отчёте.
- **База знаний** имеет закреплённое меню: «Объекты», «Атрибуты», «База вопросов», два вида правил, «Источники фото» и «Исходные JSON». Показывается только выбранный подраздел; большие таблицы прокручиваются внутри своей области. Таблицы объектов и текущих оценок содержат миниатюры напитков. Таблица вопросов содержит номер, миниатюру, текст, группу, параметр с кодом, все варианты с кодами (включая `null`), ссылки на правила, использующие параметр в условии и в выводе. Для выводимых параметров указана причина возможного пропуска. Вопросы и правила доступны для текстового поиска. Таблицы правил показывают ЕСЛИ, ТО, операцию и вес каждого действия, объяснение. Каждый исходный JSON-файл раскрывается отдельно в режиме чтения.
- **Рабочая база данных** также разделена меню: параметры, история ответов, журнал правил, оценки всех 20 объектов, снимок JSON. Для параметров видны состояния «Не задан», «Ответ: не важно», «Пропущен (выведен правилом…)», значения и источники. История показывает выводы каждого шага. В оценках видны исходная сумма, нормированная оценка, число активных правил (включая нулевые вклады) и раскрываемые вклады. Все разделы и их счётчики обновляются при ответе, возврате и перезапуске; выбранный подраздел сохраняется. «Скачать JSON» выгружает `{facts, log, answers, step}` через Blob локально, без сервера.
- **О системе**: архитектура и механизм вывода. Вкладки управляются стрелками влево/вправо, Home и End; кнопки доступны через Tab и Enter/пробел.

## Формат базы знаний

Вопрос содержит `id`, `param`, `group`, `label`, `text`, `options`, `image`, `imageAlt`. Путь `image` задаётся относительно корня сайта, например `img/questions/Q01.svg`; `imageAlt` — русское описание для доступности. Вариант — `value` и `label`; ровно один имеет `value: null` — «Не важно / Не знаю». Каждый содержательный ответ покрыт правилом.

Все 27 иллюстраций нарисованы простыми SVG-фигурами с `viewBox="0 0 320 200"`, в единой красной, белой, тёмной палитре с бирюзовым и золотистым акцентами. Они хранятся локально и используются в вопросах консультации, таблице вопросов и итоговой цепочке. Внутри нет видимых текстов, брендов, скриптов или внешних ресурсов; русское описание находится в `<title>`.

Напиток содержит `id`, `name`, `brand`, `description`, `attributes`, `facts`, `photo`. Поле `photo` хранит `src`, `alt`, `width`, `height`, `credit`; у SVG-заглушек `credit: null`, у JPEG — полные сведения об источнике и лицензии. Изображения имеют `loading="lazy"`, `decoding="async"`, явные размеры и выводятся целиком через `object-fit: contain`. Атрибуты оцениваются от 1 до 5. У версий без сахара `hasSugar: false`, `sugar: 1`, `calories: 1`. Словари в `drinks.json` задают русские подписи и допустимые значения.

Правило «параметр + атрибут»:

```json
{
  "id": "R32",
  "type": "score",
  "if": { "param": "budget", "eq": "low" },
  "then": [{ "attr": "price", "op": "low", "weight": 4 }],
  "explain": "Бюджетный выбор повышает рейтинг доступных напитков."
}
```

Операции `high`, `low` — для числовых свойств; `eq` — для числовых и категориальных; `gte`, `lte` — для числовых порогов. Для последних трёх задаётся `value`. Отрицательный `weight` означает штраф. Правило может содержать несколько действий.

Правило «параметр + параметр»:

```json
{
  "id": "R73",
  "type": "derive",
  "if": { "param": "occasion", "eq": "party" },
  "then": [{ "param": "carbonationLevel", "value": "high" }],
  "explain": "Для вечеринки модель предполагает сильную газацию."
}
```

Каждому целевому параметру соответствует вопрос. Выведенный факт имеет `{value, source: "derived", ruleId}`; пользовательский — `{value, source: "user", questionId}`. Рабочая база — `{facts, log, step}`. Журнал хранит идентификатор, тип, объяснение, шаг, а для вывода — фактически добавленные значения.

После каждого ответа правила `derive` перебираются до неподвижной точки. Добавляются только неизвестные параметры: явный ответ не перезаписывается, при конфликте выводов выигрывает первое правило в файле. Конечное число параметров и запрет перезаписи гарантируют остановку при циклах. Вопросы известных параметров пропускаются. Затем учитываются все подходящие правила `score`; повторный расчёт не удваивает вклады или журнал. Возврат воспроизводит оставшиеся ответы с нуля.

## Формула рейтинга

При значении атрибута `x` и весе `w`:

- `high`: `w × x`;
- `low`: `w × (6 − x)`;
- `eq`, `gte`, `lte`: `w` при выполнении условия, иначе 0.

Исходная сумма `S` складывается из вкладов активных правил. Для каждого действия `high/low` теоретические границы — минимум и максимум из `w` и `5w`; для проверок — из 0 и `w`. Суммы нижних и верхних границ дают `L` и `U`. Оценка: `100 × (S − L) / (U − L)`, ограниченная диапазоном 0–100 и округлённая до десятых. При `L = U`, включая отсутствие ответов, все получают **50**.

Это шкала соответствия, не вероятность. Теоретические границы могут быть недостижимы одновременно, поэтому лучший напиток не обязан получать 100. Сортировка: исходная сумма по убыванию, популярность по убыванию, название с русской локалью, идентификатор. Для каждого объекта сохраняются правило, объяснение, баллы и расчёт отдельных действий.
